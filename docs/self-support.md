# Самоподдержка: агент из контейнера обслуживает хост

По умолчанию контейнерный агент песочница: он видит только `/workspace`,
свои данные и сеть — хоста для него не существует. Режим **self-support**
даёт ему мосты, чтобы он мог сам поддерживать kit на этой машине.

## Что даёт

С файлом `docker-compose.selfhost.yml` агент внутри контейнера получает:

- **Docker-демон хоста** (`/var/run/docker.sock`) — может смотреть логи,
  рестартовать сервисы, пересобирать образы, обновлять стек.
- **Репозиторий kit'а** (`/kit`, read-write) — может править конфиги,
  делать `git pull`, редактировать `docker-compose.yml` и `.env`.

В образ уже включены Docker CLI и compose-плагин (запинены
`ARG DOCKER_CLI_VERSION`, `ARG DOCKER_COMPOSE_VERSION` в `opencode/Dockerfile`).

## Как включить

```bash
docker compose -f docker-compose.yml -f docker-compose.selfhost.yml up -d
```

Отключить — просто убрать второй `-f` и пересоздать контейнеры.

## Как пользоваться (изнутри)

```bash
cd /kit                      # репозиторий kit'а
docker compose ps            # состояние стек
docker compose logs -f bot   # логи
docker compose build opencode && docker compose up -d   # обновить себя
```

`.env` и все конфиги — в `/kit`; изменения видны хосту сразу.

## Безопасность — прочитайте

`/var/run/docker.sock` внутри контейнера эквивалентен **root на хосте**:
через демон можно смонтировать любую папку хоста в любой контейнер.
Это осознанный компромисс для личного self-hosted ассистента, но:

- Однопользовательский бот (один `TELEGRAM_ALLOWED_USER_ID`) — главный
  барьер: чужие не могут просить агента выполнить опасное.
- Для параноидального режима ставьте socket-proxy (фильтрующий прокси
  перед сокетом) — отдельная задача, не входит в kit по умолчанию.
- Не включайте self-support на многопользовательских/публичных инстансах.

## Границы

Windows-уровень хоста (процессы вне Docker, планировщик, файлы вне
смонтированных путей) из контейнера недоступен — это осознанная граница.
Для таких задач есть хост: ты.

## Откат

Убрать `-f docker-compose.selfhost.yml`, пересоздать контейнеры. Образ
остаётся тем же (CLI внутри безвреден без доступа к сокету).
