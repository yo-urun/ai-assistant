# Архитектура

```
                         Telegram
                            |
                            v
              +-----------------------------+
              |            bot              |   grinev/opencode-telegram-bot (MIT)
              |  сессии, голос (STT), файлы |   тонкий мост, свой агент не нужен
              +-----------------------------+
                            |
                HTTP API V2 (пароль из .env)
                            v
              +-----------------------------+
              |          opencode           |   ядро агента: провайдеры,
              |  сессии, MCP, permissions   |   модели, история, инструменты
              +-----------------------------+
                     |                  ^
            MCP (graphiti)              | LLM (API)
                     v                  |
              +-------------+    +--------------+
              |  graphiti   |    |   provider   |
              | MCP-сервер  |    | OpenAI/…     |
              +-------------+    +--------------+
                     |
                     v
              +-------------+
              |  falkordb   |   граф памяти (volume)
              +-------------+
```

## Поток

1. Пользователь пишет боту в Telegram (текст, голос, файл).
2. Голос уходит в Whisper-совместимый **STT API**, возвращается текстом
   (встроено в бота, пишем только ключи).
3. Бот создаёт/выбирает сессию в **OpenCode V2** и передаёт промпт.
4. OpenCode через **MCP** обращается к **Graphiti** за фактами; Graphiti
   хранит граф в **FalkorDB**.
5. Ответ стримится обратно в Telegram; бот умеет озвучку (TTS, опц.).

## Сервисы (docker compose)

| Сервис     | Роль                                   | Том               |
|------------|----------------------------------------|-------------------|
| `opencode` | ядро агента, HTTP API V2 на :49374     | `opencode_data`   |
| `bot`      | Telegram-мост (grinev)                 | `bot_data`        |
| `graphiti` | MCP-сервер долговременной памяти       | —                 |
| `falkordb` | графовая база                          | `falkordb_data`   |

Рабочая папка агента — `/workspace` в контейнере `opencode`. По умолчанию это
изолированный том `workspace`; если задать `WORKSPACE_DIR` в `.env`, туда
монтируется реальная папка с хоста (см. «Кодинг с телефона» ниже).

## Авторизация

OpenCode V2 требует пароль к серверу. Он берётся из `OPENCODE_SERVER_PASSWORD`:
сервис `opencode` фиксирует его через `opencode service set password`, а бот
передаёт то же значение в заголовке. Оба читают один `.env`.

## Ассистент и кодер в одном

Агентов несколько, выбор — прямо в боте (кнопка агента внизу клавиатуры;
в списке все primary-агенты из OpenCode API):

- **`assistant`** (по умолчанию) — обычный чат; правка и запись файлов запрещены.
- **`build`** (встроенный) — кодинг-агент: читает и правит файлы в рабочей папке.
- **`plan`** (встроенный) — планирование и исследование без правок файлов.

## Кодинг с телефона (границы)

Сам кодинг идёт через HTTP API OpenCode, поэтому работает из контейнера: вы
пишете боту, агент правит файлы в `/workspace`, ответы и диффы приходят в чат.

Чтобы агент правил **ваши** файлы, а не изолированный том, задайте в `.env`
`WORKSPACE_DIR` — абсолютный путь к папке с кодом (прямые слэши,
например `C:/Users/me/project`). Папка смонтируется в `/workspace`.

Образ бота содержит только бота. Команды, которым нужен хостовый файловый
доступ — `/open`, `/ls`, `/worktree`, `/opencode_start`, `/opencode_stop` —
в контейнере недоступны (навигация по файлам и запуск сервера). Если нужны и
они — запустите бота на хосте (см. документацию grinev).
