# Индексация кодовой базы (для крупных проектов)

Для маленьких репозиториев агенту хватает grep и чтения файлов. Индексация
нужна, когда проект большой: десятки тысяч файлов, и вопрос «где это
реализовано» стоит минут чтения. Здесь — опенсорсные варианты, встроенные
в kit **выключенными по умолчанию**: включаются только там, где реально надо.

## Что встроено: Serena (рекомендовано по умолчанию)

[Serena](https://github.com/oraios/serena) — MCP-инструментарий символ-уровня
через language-серверы (LSP): поиск символов, ссылки, иерархия, точечные
правки. 40+ языков. Ноль инфраструктуры: не строит индекс, не тратит токены
на эмбеддинги, работает на лету. Лицензия: MIT (LSP-ядро) / GPL-3 (приложение).

В `opencode/opencode.jsonc` он уже прописан **с `enabled: false`**:

```jsonc
"serena": {
  "type": "local",
  "command": ["uvx", "--from", "git+https://github.com/oraios/serena",
              "serena", "start-mcp-server", "--context", "ide-assistant"],
  "enabled": false
}
```

Включить: поставь `"enabled": true` и `docker compose up -d`. Первый запуск
скачает language-серверы нужных языков (кэшируются). Контекст `ide-assistant`
отключает дублирующие файловые утилиты — в kit'е они уже есть у агента.

Альтернатива без правки глобального конфига: положи `opencode.json` с этим
блоком (`"enabled": true`) в корень конкретного проекта — Serena включится
только там.

## Вариант: open-codebase-index (семантический поиск)

[open-codebase-index](https://github.com/Helweg/open-codebase-index) — гибрид
эмбеддингов + BM25, нативный плагин для OpenCode, локальный SQLite-индекс,
инкрементальная переиндексация с учётом веток. Ставится через npm:

```bash
npm install -g open-codebase-index open-codebase-index-mcp
```

Выбери провайдер эмбеддингов: Ollama (локально, бесплатно), OpenAI,
OpenRouter (OpenAI-совместимый endpoint) — понадобится ключ или локальный
Ollama. Индекс живёт в `.opencode/` проекта и попадает в `.gitignore`.

Когда выбирать вместо Serena: вопросы формулируются смыслом («где мы
публикуем события заказа?»), а не именами символов; проект полиглотный;
нужен поиск по истории вызовов. Плата: время на первичную индексацию,
место под индекс, расходы на эмбеддинги (если не Ollama).

## Продвинутый вариант: codesearch (multi-repo)

[codesearch](https://github.com/flupkede/codesearch) — Rust-бинарник, гибрид
vector+BM25, полностью офлайн, режим `serve` для поиска сразу по нескольким
репозиториям (кросс-репо ранжирование). Нужен, когда работаешь с группой
сервисов одновременно. Для одиночного проекта избыточен.

## Сводка

| | Serena | open-codebase-index | codesearch |
|---|---|---|---|
| Тип | LSP, символы | эмбеддинги + BM25 | эмбеддинги + BM25, multi-repo |
| Инфраструктура | ноль | SQLite-индекс | локальные векторы |
| Расходы | ноль | эмбеддинги (или Ollama) | ноль (fastembed локально) |
| Включение | флаг в конфиге | npm + индексация | бинарник + индексация |
| Когда | большие проекты, точные символы | смысловой поиск | много репо сразу |

## Правило

Маленький проект → ничего не включай. Большой проект → включай Serena;
если символьного поиска мало — добавляй open-codebase-index. После работы
над проектом можно выключить обратно.
