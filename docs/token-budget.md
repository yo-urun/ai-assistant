# Бюджет токенов: как уменьшить счёт в 2–4 раза

Эта страница — про деньги, а не про качество ответов. Здесь собрано, куда
реально уходят токены в этой сборке, что уже изменено по умолчанию и какие
ручки крутить дальше.

## Куда уходят токены

У длинной сессии в Telegram три статьи расхода:

| Статья | Что это | Как выглядит в счёте |
|---|---|---|
| **Вход (cached)** | Вся история сессии, которую провайдер уже видел | `cached input`: десятки миллионов при сотнях ходов |
| **Вход (обычный)** | Системный промпт, схемы инструментов, новый текст | `input`: ~3–8k на ход |
| **Выход** | Ответы ассистента, вызовы инструментов, сводки | `output`: ~0.5–2k на ход |

Плюс отдельная строка у **Graphiti**: извлечение сущностей и связей из каждого
эпизода. У Graphiti **нет prompt cache**, поэтому каждый символ эпизода
оплачивается полностью. Именно поэтому «просто батчить» недостаточно — важно,
что именно попадает в батч.

> Важно: `cached input` дешевле обычного (обычно 10–50% цены), но не бесплатен.
> При 20M cached и контексте ~60k это ~330 ходов в одной сессии. Главный рычаг —
> не «оптимизировать кэш», а **сократить историю и число ходов с большим
> контекстом**.

## Что уже изменено по умолчанию

### 1. Компакция контекста (OpenCode V2)

В `opencode/opencode.jsonc`:

```jsonc
"compaction": {
  "auto": true,
  "keep": { "tokens": 8000 },
  "buffer": 96000
}
```

- **`keep.tokens: 8000`** — рядом со сводкой остаётся ~8k недавнего разговора
  вместо 15k по умолчанию. Остальное заменяется сводкой.
- **`buffer: 96000`** — компакция стартует за 96k до лимита модели. Для модели
  на 128k это порог ~32k: контекст не успевает разрастись до 100k+, а средний
  размер запроса падает в разы.
- Для моделей с меньшим контекстом OpenCode игнорирует `buffer` больше лимита и
  сжимает near-limit — ничего не ломается.
- Компакция **lossy**: если для вас важны точные детали давних сообщений,
  поднимите `keep.tokens` до 12000–16000. Память в графе при этом не страдает.

В OpenCode V2 **нет** опции «слайдинг-окно по числу сообщений»
(`last_messages` из V1). Аналог — `compaction.keep.tokens` + `buffer` выше.

#### Своя модель (Ollama, свой endpoint): без `limit` компакции нет

Порог компакции считается как `limit.context − buffer`. Для провайдеров,
которые OpenCode знает из коробки, лимит приходит вместе с каталогом моделей.
У Ollama и своего OpenAI-совместимого endpoint каталога нет: если в блоке
`providers` у модели не указан `limit`, OpenCode считает лимит неизвестным и
**не запускает компакцию вообще** — история растёт, пока провайдер не вернёт
ошибку контекста.

Мастер установки (пункты «Ollama» и «Свой вариант») генерирует
`opencode/opencode.local.jsonc` с явным лимитом и монтирует его вместо
штатного конфига (`OPENCODE_CONFIG_FILE` в `.env`):

```jsonc
"providers": {
  "custom": {
    "name": "Custom",
    "env": ["CUSTOM_API_KEY"],
    "package": "@opencode/ai/providers/openai-compatible",
    "settings": { "baseURL": "{env:CUSTOM_BASE_URL}" },
    "models": {
      "<id модели>": {
        "name": "<id модели>",
        "limit": { "context": 128000, "output": 8192 }
      }
    }
  }
}
```

`context` — реальное окно модели (для Ollama смотрите `ollama show <модель>`),
`output` — запас на ответ. Сменили модель или окно — правьте файл и делайте
`docker compose restart opencode`. Адрес и ключ живут в `.env`
(`OLLAMA_BASE_URL`, `CUSTOM_BASE_URL`, `CUSTOM_API_KEY`), в конфиге только
ссылки `{env:...}`.

### 2. Дешёвая модель для сводок

```env
OPENCODE_SMALL_MODEL=openai/gpt-4o-mini
```

`agents.compaction.model` в конфиге берёт значение из этой переменной. Сводку
пишет дешёвая модель, а не основная. Пустое значение compose подставляет как
`OPENCODE_MODEL_PROVIDER/OPENCODE_MODEL_ID` — то есть сводки пишет модель
сессии; на неизвестную провайдеру модель OpenCode тоже откатывается на модель
сессии.

### 3. Ограничение вывода инструментов

```jsonc
"tool_output": { "max_lines": 400, "max_bytes": 16384 }
```

Дефолт (2000 строк / 50 КиБ) рассчитан на кодинг. В чате прочитанный файл или
длинный вывод команды потом тащится в каждом следующем запросе. 400 строк
хватает для документов и логов, а история растёт медленнее.

### 4. Скиллы — по требованию

Раньше в образ запекались 10 инженерных скиллов. Каждый скилл добавляет имя и
описание в системный промпт **каждого** запроса (суммарно ~1k токенов на ход),
даже если вы никогда его не вызываете.

Теперь они выключены по умолчанию. Включить:

```bash
docker build --build-arg INSTALL_SKILLS=true -t opencode-v2:local ./opencode
```

или в `docker-compose.yml`:

```yaml
build:
  context: ./opencode
  args:
    INSTALL_SKILLS: "true"
```

Подробнее — [docs/skills.md](skills.md).

### 5. Экстрактор памяти: меньше и чище эпизодов

Фоновый экстрактор (`opencode-graphiti-extractor` ≥ 0.4) теперь:

- **фильтрует мусор** — «ок», «спасибо», приветствия, команды `/start`, чистые
  эмодзи не создают эпизод;
- **режет ответы ассистента сильнее, чем реплики пользователя** (400 против 900
  символов): факты обычно в словах пользователя;
- **держит свежие строки** при переполнении батча, а не самые старые;
- **батчит дольше** (`debounceMs` 180 с вместо 90) — меньше эпизодов, меньше
  фиксированных накладных расходов на каждый вызов LLM у Graphiti;
- **отдаёт память компактно**: `memory(search)` возвращает top-5 фактов и узлов
  плотными строками без UUID, `group_id` и списков эпизодов, с лимитом 2000
  символов вместо JSON до 4000.

Ручки — в `.env` (все опциональны):

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `GRAPHITI_DEBOUNCE_MS` | `180000` | пауза простоя перед отправкой батча |
| `GRAPHITI_MIN_TURNS` | `4` | не отправлять батчи короче |
| `GRAPHITI_MAX_CHARS` | `12000` | лимит тела эпизода |
| `GRAPHITI_PER_TURN_MAX` | `900` | символов от реплики пользователя |
| `GRAPHITI_ASSISTANT_MAX` | `400` | символов от ответа ассистента |
| `GRAPHITI_MIN_TURN_CHARS` | `16` | порог отбрасывания коротких реплик |
| `GRAPHITI_SKIP_LOW_VALUE` | `true` | фильтр приветствий/команд |
| `GRAPHITI_SEARCH_TOP_K` | `5` | фактов и узлов в ответе `memory(search)` |
| `GRAPHITI_SEARCH_MAX_CHARS` | `2000` | лимит ответа поиска |

Компромисс: длинный debounce означает, что память появляется в графе через
несколько минут после разговора, а не сразу. Если память нужна «сейчас»,
попросите ассистента явно: `memory add` пишет заметку немедленно.

### 6. Graphiti: дешёвая модель извлечения

```env
GRAPHITI_MODEL=gpt-4o-mini
GRAPHITI_SEMAPHORE_LIMIT=2
```

- Извлечение сущностей не требует reasoning-модели: это структурный JSON по
  тексту. Дешёвая mini-модель даёт почти то же качество при кратно меньшей цене.
- Слишком маленькие локальные модели часто ломают JSON-схему — тогда задайте
  `LLM_STRUCTURED_OUTPUT_MODE=json_object` (см. документацию Graphiti MCP).
- `SEMAPHORE_LIMIT` не влияет на цену за токен, но убирает пики и 429.
- `GRAPHITI_TELEMETRY_ENABLED=false` — меньше фоновой сети.

Если ваш образ Graphiti не читает `MODEL_NAME`, задайте модель в его
`config.yaml` (`llm.model`) — имена переменных зависят от сборки.

### 7. Прокси и базовый URL

Graphiti читает `OPENAI_API_URL` (не `OPENAI_BASE_URL`). Compose подставляет
`OPENAI_API_URL` из `OPENAI_BASE_URL`, если первая не задана, так что старые
`.env` продолжают работать. OpenCode при этом видит `OPENAI_BASE_URL` как раньше.

## Что проверить у себя

1. **Размер контекста.** В боте нажмите 📊 (контекст) — видно, сколько токенов
   занимает текущая сессия. Если после наших изменений контекст всё ещё
   стабильно >40k, проверьте, что конфиг подхватился: `/reload` (V2) или
   `docker compose restart opencode`. Для Ollama и своего endpoint проверьте,
   что у модели в `opencode.local.jsonc` есть `limit` (см. раздел выше) —
   без него компакция не включается.
2. **Сводки.** Первая компакция после обновления перепишет старую историю
   один раз — это разовый расход. Дальше потолок будет ~32k.
3. **Экстрактор.** `docker compose exec opencode tail -n 50 /root/.config/opencode/graphiti-extractor.log`
   — строки `queued`/`submitted` показывают размер эпизодов (`chars`). Если там
   регулярно 10000+, уменьшите `GRAPHITI_MAX_CHARS` или `GRAPHITI_PER_TURN_MAX`.
4. **Graphiti.** `docker compose logs graphiti | grep -i "Using LLM"` — модель
   должна быть дешёвой.
5. **Счёт провайдера.** Смотрите не общий input, а `cached` и `output` отдельно:
   cached должен упасть первым (история короче), output — после того как
   ассистент привыкнет к «1–5 предложений».

## Чего делать не нужно

- **Искать «sliding window last_messages»** — в V2 такой опции нет.
- **Переносить дату/окружение в конец промпта** — OpenCode V2 уже добавляет
  динамические метки (`Today's date`, `<env>`) в конец системного промпта, а не
  в начало. Кэш от смены минуты не ломается.
- **Резать top-K «инжекта памяти»** — в этой сборке память **не инжектится** в
  каждый запрос: экстрактор только пишет, а читает агент по требованию через
  `memory(search)`. Экономия уже сделана в формате ответа этого инструмента.
- **Ставить локальный Whisper «для экономии»** — бот умеет только
  Whisper-совместимый HTTP API; локальный контейнер в стек не входит. Мастер
  предлагает Groq (`STT_MODEL=whisper-large-v3-turbo`, есть бесплатный тариф),
  OpenAI или свой OpenAI-совместимый STT. Обрезки тишины в боте нет: она
  приходит уже сжатой Telegram-ом, а лишние секунды зависят от записи
  пользователя.

## Пресеты

**Экономия (по умолчанию):** как в репозитории. Ориентир — 2–4× меньше input и
cached на длинной сессии.

**Качество:** `compaction.keep.tokens: 16000`, `buffer: 64000` (порог ~64k на
128k-модели), `GRAPHITI_MAX_CHARS=18000`, `GRAPHITI_DEBOUNCE_MS=90000`,
`INSTALL_SKILLS=true`. Дороже, но лучше помнит детали давних сообщений.

**Максимальная экономия:** `keep.tokens: 4000`, `buffer: 112000` (порог ~16k),
`GRAPHITI_MAX_CHARS=6000`, `GRAPHITI_PER_TURN_MAX=500`,
`GRAPHITI_ASSISTANT_MAX=250`. Подходит для коротких бытовых поручений; для
длинных обсуждений будет терять контекст.
